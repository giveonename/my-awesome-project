## Decisions

- 模板 Web 前端（frontend/）与部署套件（k8s/nginx/release 工具）全部删除，只保留小程序+后端
- 删 discover/evaluation 两死页面，ootd 保留并接入首页入口
- 主题方向 A：深墨绿 #2D6A4F + 奶油白 #FAF7F2，阴影转暖棕黑，全量换色而非只换主色
- 文本模型 MiMo → DeepSeek（模型 ID 必须 `deepseek-flash`，公告营销名不可用）；视觉同走该 API
- 试衣 → qwen-image-3.0（同步 API），本地图 Base64 上传，**不再依赖 OSS**；整 outfit 直传不拆分
- 提示词属性只写"来自真实衣物元数据"的内容；衣长交由商品图（写错长度会扭曲商品，已实验证实）
- 搭配池 P1 架构：预生成池 + arq worker + Redis 状态（刻意不加表——迁移图损坏）；通知走应用内（横幅插播）而非系统推送；成本帽：每日 2 批补货
- 头像昵称只能走微信官方能力 chooseAvatar / input type=nickname（2022 政策）；头像存相对路径、响应时实时签名

## Pitfalls

- **容器⇄仓库漂移（本会话最大的坑）**：旧镜像+sync-backend 补丁导致容器跑 6 月代码（ngrok 图片化石、oss_service 丢失、分类器只在容器内）。根治=镜像重建工作流；改后端用 `docker compose up -d --build backend worker`，弃用 sync-backend.cmd
- **SQLAlchemy MissingGreenlet**：async 会话里访问未 eager load 的关系即抛错。Mode A 查询（随机复用的"已有搭配"）从未真正跑过，数据长齐后爆发；`Outfit.feedback` 已设 `lazy="selectin"` 兜底。新查询务必 selectinload(items→item, feedback, family_ratings)
- **qwen-image-3.0 并发配额严**：6 并发全灭（Throttling.RateQuota）→ 串行 Semaphore(1) + 退避重试（≤3 次，20/40s）
- **arq enqueue 必须带 `_queue_name="arq:tagging"`**：漏了会进默认队列，worker 永不消费（排查了 4 轮才揪出）
- **worker 容器缺 DASHSCOPE_* 环境变量**：试衣生成搬进 worker 后，compose worker 段需补（已加）；且 `get_db_session(ctx)` 是**同步函数**，await 会 TypeError
- **微信 2022 政策**：头像昵称不可静默获取，只能 chooseAvatar/type=nickname
- **Docker 构建国内网络**：Docker Hub 拉底座超时、apt/pip 龟速 → registry mirror + 阿里云源是必需项，不是优化项
- **.env 优先级**：compose 注入的根 .env 变量胜过 backend/.env（pydantic env > dotenv），改配置永远改根 .env
- **sass @import 弃用警告**里混的乱码字符 = scss 文件 UTF-8 BOM；scroll-view 的 padding 在 webview 渲染模式仅部分支持
- **测试脚本陷阱**：heredoc 大段 Python 多次被 bash 撕裂 → 写成脚本文件执行最稳；`grep -c` 计数为 0 时退出码 1 会断 `&&` 链
